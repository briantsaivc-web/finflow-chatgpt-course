# 第七章｜替每一次成功留下存檔點

當 AI 改 A 壞 B，最可怕的不是錯誤本身，而是你已經不知道上一個正常版本在哪裡。GitHub 的價值因此不是展示程式，而是替每一次成功留下可辨識、可回去的存檔點。

Repository 是專案櫃，commit 是寫著說明的存檔，push 是把本機存檔放到雲端，branch 則是從正常版本分出去的試驗路線。

好的 commit 不寫 `update`，而是寫「修正 NPC 在商城冷卻時重複購買造成的死鎖」。半年後的你才能判斷哪一筆改了什麼。

新手最重要的 Git 習慣不是背指令，而是縮小每次變更。一個 commit 只處理一個主題；推送前先看 `git status --short`；大改之前開 branch；改壞時先停止，不要立刻強制覆蓋。

本章會讓讀者故意改壞一段文字，再從歷史找出最後正常存檔。只有親自救回一次作品，GitHub 才會從抽象名詞變成真正的時光機。
