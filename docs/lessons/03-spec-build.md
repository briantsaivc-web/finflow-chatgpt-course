# 單元 3｜跟 AI 寫規格與第一版

## 為什麼先要規格書

程式碼可能看不懂，但規格書是人話。它是你在 AI 動手前的審核點。

如果方向錯了，在文字階段改一句話很便宜；等整份程式完成再改，常會出現「改 A 壞 B」。

## 第一步：生成規格書

準備好 `idea-v01.md`、`mvp-v01.md`，使用 [P03 規格書卡](../prompts/P03-spec.md)。

## 第二步：只檢查五件事

1. **玩法**：玩家一局到底做什麼？
2. **資料**：有哪些職業、事件與玩家數值？
3. **流程**：開始、每回合、結束的順序？
4. **例外**：錢不夠、按兩次、資料缺漏時怎麼辦？
5. **完成條件**：如何證明第一版能交付？

看到 `待確認` 就回答；看到 AI 偷加的功能就刪掉。

## 第三步：請 AI 先復述

```text
在寫程式前，請先用十點以內復述你理解的本版範圍、三條鐵律、
明確不做的功能，以及完成驗收條件。等我回覆「核可」後再動工。
```

## 第四步：生成第一版

```text
核可。請依規格書製作 v0.1。
只完成已核可範圍，不得順便增加其他功能。
請交付完整 index.html、版本號、變更摘要、人工測試步驟與已知限制。
```

## 第五步：不要看一眼就說完成

使用 [T01 第一版驗收表](../worksheets/T01-acceptance.md)，至少完整玩三局：

- 一局正常選擇
- 一局故意拒絕所有投資
- 一局故意快速連點與亂按
