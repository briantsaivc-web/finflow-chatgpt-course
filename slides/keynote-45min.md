# 不會寫程式，照樣做出一款真的遊戲

從一個財商教育念頭，到朋友真的能玩的多人遊戲

---

# 真正的財務關卡，沒有人讓我們先練習

不是複利公式。

而是誘惑、恐懼、面子與旁人慫恿出現的那一刻。

---

# 我想做一個安全的練習場

可以衝動、可以虧損、可以被騙。

遊戲結束時說：「還好這只是遊戲。」

但體悟是真的。

---

# 問題是：我不會寫程式

我知道自己想做什麼。

卻不知道怎麼把它變成螢幕上能跑的東西。

---

# AI 沒有替我想出 FinFlow

我負責：方向、規則、取捨、試玩與驗收。

AI 負責：整理、提案、實作、檢查與修正。

---

# 這不是一次生成，而是二十次交付疊出來

第一版能動之後，真正的開發才開始。

---

# 開發循環其實只有七個動作

想清楚 → 寫規格 → 做小版 → 自己玩 → 找差異 → 修正 → 存檔

---

# 新手最大的錯，不是不會寫程式

而是一開始就想做完整版。

---

# MVP 必須能完成一次體驗

開始、玩家動作、結果、結束。

少一個都只是畫面，不是遊戲。

---

# 三條鐵律，讓看不懂程式的人也能把關

1. 規則與畫面分開
2. 卡片內容集中成資料
3. 每筆金錢變動留下紀錄

---

# 先要規格書，再要程式

規格書是你看得懂、也喊得停的審核點。

---

# AI 說「完成」，不代表真的完成

你必須實際玩、故意亂按，並對照預期結果。

---

# 不懂術語，也能把 bug 說清楚

我做了什麼＋預期什麼＋實際什麼＋截圖

---

# 「畫面出現怪符號」就是合格的起點

誠實描述你看到的，不要假裝自己懂原因。

---

# 六人局曾卡在 NPC 想做一個不能做的動作

真正的修復不是「現在能玩」。

而是替這隻 bug 留下一個永遠抓得到它的測試。

---

# GitHub 是時光機，不是工程師俱樂部

commit 是存檔。

push 是把存檔放上雲端。

---

# UI 改四次，不代表前面三次都白做

做出來、玩一輪、看見問題，才知道下一版該怎麼改。

---

# 真正的使用者，不知道你的「正確操作」

所以他們會走出你從沒想過的路徑。

---

# 三位玩家，一次抓出五個自己沒發現的問題

找人測試不是形式，是產品開始面對現實。

---

# 一個網址，讓作品離開你的電腦

GitHub Pages 讓朋友不必安裝任何東西就能玩。

---

# 你今天就能完成的第一個作品

一個按鈕、分數、完成條件、重新開始。

十五分鐘，不是十五週。

---

# 做完之後，再把它改成自己的

換主題、換資料、換規則、換畫面。

複製只是起點，改造才是能力。

---

# 多人連線不是入門門檻

先完成單機版。

真的需要不同裝置同步，才加入 Firebase。

---

# 從能玩走向能長大

安全網先建立，再拆成資料層、邏輯層與畫面層。

---

# 你不需要先成為工程師

你需要完成第一個作品，並讓下一版比上一版更好。
