# 兩小時零基礎試教 Run of Show

## 試教目標

學員在 120 分鐘內完成一個會動的瀏覽器作品、第一次 AI 規格對話、一次 Bug 回報與一次 Git commit，並知道如何繼續升級 CP02～CP06。

## 講師準備

- 課前 30 分鐘測試 CP01、CP06 與 GitHub Pages 網址。
- 準備一個故意壞掉的版本，現場示範「預期／實際／證據」。
- 不在前 25 分鐘解釋 JavaScript 語法。
- 每段結束前保留 2 分鐘驗收，不以「大家有沒有問題」取代操作檢查。

## 流程

### 00–10 分｜成品先行

- 播放或操作 CP06。
- 問：「如果今天只做到其中一件事，你最想做到什麼？」
- 驗收：每位學員寫下一個可觀察成果。

### 10–25 分｜第一個成功

- 打開 CP01。
- 修改標題、按鈕文字與一次計分規則。
- 驗收：重新整理後仍可操作。

### 25–45 分｜題目與 MVP

- 完成一句話作品公式。
- 將功能分為現在做、之後做、也許不做。
- 驗收：MVP 具備開始、選擇、結果。

### 45–65 分｜與 AI 分工

- 使用 P07 規格核可卡。
- 要求 AI 先復述，不立即寫程式。
- 驗收：規格包含玩法、資料、流程、例外與完成條件。

### 65–85 分｜Debug

- 操作故障版。
- 使用 P04／P08 回報 Bug。
- 驗收：學員能說出操作、預期、實際、證據。

### 85–105 分｜GitHub 時光機

- 建立第一次 commit。
- 解釋 repository、commit、push。
- 驗收：Git 歷史中看得到人類可讀的版本說明。

### 105–115 分｜互測

- 兩人交換作品，不教對方操作。
- 只記錄第一個動作與第一次卡住。
- 驗收：把意見翻譯成可驗證問題，不直接照單全收解法。

### 115–120 分｜收尾

- 每人選擇下一個 checkpoint。
- 填寫出口單：今天完成什麼、下一步是什麼、目前最大阻礙。

## 中止條件

若超過三分之一學員在同一步驟卡住，停止增加新內容，改用投影共同完成一次；若 Git 登入或網路阻塞，先保存本機成果，不犧牲作品完成感。
